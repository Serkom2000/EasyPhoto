# EasyPhoto

<!-- impeccable:product-schema 1 -->

## Platform

web

## Product Purpose

Локальная фотомастерская с русским интерфейсом: создание фотографии по описанию, изменение исходного снимка и сохранение результата без сборки графа нод в основном интерфейсе. ComfyUI выполняет генерацию в фоне.

## Operating Context

Основной установочный сценарий — Windows с видеокартой NVIDIA. Установщик подготавливает ComfyUI Portable с собственным Python и библиотеками. После подготовки движка и весов генерация выполняется локально без интернета. Интернет нужен для установки и получения обновлений. Существующий ComfyUI можно подключить отдельно, указав его папку в настройках.

В студии пользователь выбирает режим, вводит описание, выбирает набор или семейство и модель, проверяет необходимые компоненты и запускает генерацию. Результат можно скачать, использовать для дальнейшего изменения или найти в истории с параметрами.

## Capabilities and Constraints

- Встроенные семейства: SD 1.5, SDXL, SD Turbo, SDXL Turbo, FLUX.1 Dev и FLUX.1 Schnell. Пользователь выбирает семейство по описанию модели; универсального автоматического определения архитектуры нет. Наличие файла в списке не доказывает совместимость с выбранным семейством.
- «Мой набор» сохраняет имя, семейство, загрузчик, модель, VAE, текстовые энкодеры, FLUX Guidance, LoRA с силой, шаги и CFG. Это повторно используемая конфигурация моделей и параметров, а не сохранённое изображение или полный снимок всех полей студии. Набор с тем же именем заменяется; хранится до 100 наборов локально в `data/presets.json`.
- Компоненты VAE, энкодеры и LoRA сгруппированы в раскрываемый блок. Для отдельного FLUX блок раскрывается и нужны diffusion model, CLIP-L, T5 и совместимый VAE. Альтернатива — полный checkpoint с компонентами. Совместимость VAE, LoRA и энкодеров пользователь проверяет по документации модели. Поддерживается до восьми LoRA.
- Раздел «Модели» импортирует локальные `.safetensors` и `.gguf` по выбранной категории: checkpoint, diffusion model / UNet, VAE, LoRA, текстовый энкодер или ControlNet. Файл копируется в соответствующую папку настроенного движка. Выбор категории не устанавливает поддержку формата или архитектуры.
- Другие архитектуры подключаются JSON-профилем с workflow в API-формате и явными `bindings` полей студии к входам узлов. Импортированный профиль появляется в выборе семейства. Профиль использует уже подготовленные веса и узлы движка; EasyPhoto не устанавливает произвольные custom nodes. Для GGUF нужны подходящие узлы и совместимый пользовательский профиль. Сам импорт файла GGUF этого не обеспечивает.
- Пользовательский профиль обязан связывать `prompt`. Изменение снимка требует binding `image`. Кисть и режим «Поза» не подключаются к произвольному профилю автоматически: соответствующее поведение нужно подготовить внутри workflow. Поля студии заменяют только явно указанные bindings.
- Встроенные режимы включают создание по тексту, изменение всего фото, изменение области с маской кистью и генерацию по готовой OpenPose-карте. Встроенная «Поза» предназначена для SD; FLUX ControlNet требует совместимого пользовательского workflow. Автоматическое извлечение позы из обычного фото, автоматическое выделение фона и сохранение личности при смене позы не подключены. Автоперевода описания нет.
- Небольшой Updater получает изменившиеся файлы EasyPhoto, проверяет размер и SHA-256 и сохраняет резервные копии для восстановления незавершённого обновления. Он не заменяет веса моделей, фотографии, пользовательские наборы и профили, runtime ComfyUI или его библиотеки. Движок и его зависимости обновляются отдельно. Обновление запускается для установленной программы после окончания генерации; исходный Git checkout обновляют через Git.

## Brand Commitments

Сохраняются имя EasyPhoto, русский интерфейс и существующая подача «ваша фотомастерская». Текущее расширение продолжает существующий интерфейс студии; новая визуальная система этим документом не учреждается.

## Product Principles

- Основной путь остаётся студией с понятным описанием кадра и выбором готового набора.
- Сложность компонентов раскрывается по необходимости; расширяемость обеспечивается явными профилями и подготовленным движком.
- Указывать границы совместимости и недостающие компоненты вместо обещания универсальной поддержки моделей.
- Сохранять локальные фотографии, веса и пользовательские конфигурации при обновлении приложения.
