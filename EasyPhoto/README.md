# EasyPhoto

Локальная фотомастерская с русским интерфейсом. ComfyUI работает в фоне; пользователю не нужно собирать ноды.

## Windows: установка одной кнопкой

1. Распакуйте **весь архив установщика** в отдельную папку. Рядом с `EasyPhoto-Setup.exe` должны остаться `payload.7z`, `package.json` и папка `installer`.
2. Откройте **EasyPhoto-Setup.exe**, выберите папку с минимум 18 ГБ свободного места и нажмите **Установить EasyPhoto**. Папка должна быть пустой. Нужны видеокарта NVIDIA с установленным драйвером и интернет на время установки.
3. Две модели уже в архиве. Установщик проверит файлы, скачает официальный ComfyUI Portable (около 1,8 ГБ) вместе с Python и библиотеками, распакует его в папку приложения и создаст ярлык на рабочем столе. Системный Python не используется.
4. Нажмите **Открыть мастерскую** или запустите ярлык **EasyPhoto**. Окно запуска покажет подготовку движка, после чего откроется студия в браузере.
5. В правом верхнем углу есть кнопка **Инструкция**: создание, редактирование, кисть, модели, настройки и готовый пример запроса.

После установки генерация работает без интернета. Модели по умолчанию: **SDXL Base 1.0** и **DreamShaper 8**. При смене модели из комплекта размеры форматов подбираются автоматически. Свои полные checkpoints SDXL / SD 1.5 добавляются в разделе **Модели**. Скачивания весов внутри программы нет.

При медленной загрузке смотрите мегабайты и скорость, а не только процент. Распаковка десятков тысяч файлов на жёсткий диск может идти долго; на этом этапе индикатор показывает занятость. После сетевой ошибки можно повторить установку в ту же папку. Если там уже подготовлен совместимый runtime с версией движка, он проверяется и используется повторно.

Закрытие окна запуска EasyPhoto завершает сервер приложения и принадлежащий ему движок. Закрытие одной вкладки браузера их не останавливает. Журналы: `data/logs`.

## Для разработчика: сборка установщика

Модели с исходными именами лежат в `models/checkpoints`; размеры и SHA-256 — в `models/manifest.json`. Подготовленный runtime на машине сборщика нужен для проверки весов и упаковки, но в установочный payload он не входит.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/build-installer.ps1 -OutputDirectory D:\EasyPhoto-build
```

Скрипт компилирует нативные EXE средствами .NET Framework Windows, упаковывает приложение с моделями, сохраняет хеш payload и проверяет архив. Весь созданный каталог распространяется одним ZIP-архивом. Полный автономный комплект также можно собрать отдельным `scripts/package.ps1`, но основной установщик скачивает движок при установке.

Модели из комплекта находятся в `models/checkpoints`; относительный `extra_model_paths.yaml` позволяет переносить установленную папку. Личные снимки, история и журналы в установочный архив не включаются.

## Если ComfyUI уже установлен

Запустите его на `127.0.0.1:8188`. EasyPhoto — Python-приложение без сторонних зависимостей:

```bash
python app.py
```

Запускайте свой ComfyUI с параметром `--extra-model-paths-config ПУТЬ/К/EasyPhoto/extra_model_paths.yaml`, чтобы он видел модели комплекта. В настройках EasyPhoto укажите папку ComfyUI с `main.py`: в неё будут копироваться добавленные через интерфейс модели. Можно использовать Python из portable-сборки. Если сохранён путь к существующей portable-сборке, Start.bat использует и её Python. Для нестандартной установки с venv запускайте приложение подходящим Python самостоятельно.

Параметры запуска:

```bash
python app.py --no-browser --port 8787 --comfy-url http://127.0.0.1:8188
```

Linux/macOS: сам интерфейс работает с Python 3.10+, но автоматическая установка движка подготовлена только для Windows/NVIDIA. Для остальных систем установите ComfyUI отдельно. Никаких весов моделей в репозитории нет.

## Возможности первой версии

- **Создать**: текст → фото, три формата, модель, seed, число шагов, CFG, negative prompt. Один результат за задание.
- **Изменить**: загрузка JPG/PNG/WEBP, img2img и сила изменения. Исходник приводится к размерам, кратным 64, с длинной стороной до 1536 пикселей.
- **Кисть**: включите «Изменить только выделенное» и закрасьте область. Белая маска отправляется через LoadImageMask (красный канал) → VAEEncodeForInpaint. После генерации исходные пиксели вне маски возвращаются через ImageCompositeMasked. Сохраняется область вне маски в обработанном разрешении, а не исходный файл побайтно. Для замены фона закрасьте фон и опишите весь желаемый кадр. Результат зависит от модели и маски.
- **Поза**: генерация по **готовой карте OpenPose** и установленной совместимой ControlNet. Извлечение позы из фотографии, автоматическое скачивание ControlNet и перенос личности человека не реализованы. Обычная фотография не заменяет карту позы.
- **История**: результаты, параметры и повтор настроек. Для редактирования при повторе нужно снова загрузить исходник и маску. Текущая задача восстанавливается после обновления страницы.
- **Модели**: две модели в комплекте; добавление своего файла .safetensors через интерфейс с прогрессом копирования; обнаружение полных checkpoints SDXL/SD 1.5 из ComfyUI. Отдельные UNet, FLUX, LoRA и другие архитектуры не поддерживаются текущими workflow. Приложение не определяет семейство произвольного checkpoint автоматически.

SDXL лучше понимает английские описания. Автоперевода и современного редактирования командами вроде «поверни этого человека» здесь пока нет. Это первая рабочая оболочка для базовых workflow, а не готовая замена всем сценариям ComfyUI.

## Хранение

`data/outputs` — сохранённые изображения; `data/jobs` — история и параметры; `data/settings.json` — путь движка. Исходные фото и маски также попадают в локальную папку `input` ComfyUI; результаты дублируются в его `output`. Очистка этих папок пока выполняется вручную.

Сервер слушает только localhost. Интерфейс не отправляет фотографии в облачные API. Готовый комплект не скачивает модели и зависимости. При подготовке исходников движок загружается с GitHub/7-Zip. Внешних шрифтов, аналитики и подписок нет.

## Проверка разработчиком

```bash
python -m unittest discover -s tests -v
node --check web/app.js
python -m py_compile app.py
```

Тесты проверяют маршруты, генерацию/редактирование/ControlNet, загрузку изображений в ComfyUI, получение и сохранение результатов, сообщения ошибок и защиту локальных запросов. Они не запускают диффузионную модель.
